## Learned Workspace Facts

- `axle-tui` is a Rust Windows TUI that scans and installs driver updates through Windows Update COM in `src/wua.rs`. `src/session.rs` owns `plan` and `apply`. There is no PowerShell scan or install script.
- Downloads and installs are separate queues. At most 3 downloads run at once (`DOWNLOAD_SLOT_LIMIT`), smallest `max_download_size` first, ties keep plan order. Each download or install uses its own `IUpdateSession` (`on_own_session`). One install worker runs only after that package's download succeeds. A non-extension installs before an extension (title or driver class contains `extension`, ASCII case-insensitive); same rank keeps the earlier plan index. A successful install that requires reboot stops further installs; remaining packages fail with `Install stopped because a reboot is required`. A failed download does not enter the install queue.
- `plan()` drops a selected update only when another selected update lists its id in `SupersededUpdateIDs`. Titles are not a version parser.
- Search criteria stay `IsInstalled=0 and Type='Driver'`. `ServerSelection` is `ssWindowsUpdate` (value 2).
- A non-admin process can scan, but driver `Download` returns Windows Update result code 4 (`orcFailed`). Install the release binary with administrator.
- `build.rs` embeds `requireAdministrator` for the release profile and `asInvoker` otherwise. `cargo test` runs without elevation. `cargo install --path . --force` still produces a binary that raises UAC.
- Package version is `0.2.0`. A local `cargo install --path . --force` is required only when reinstalling the same version. A higher version installs over an older one. Binary path stays `%USERPROFILE%\.cargo\bin\axle-tui.exe`.
- Operation log path is `%LOCALAPPDATA%\axle-tui\ops.log`. `AXLE_LOG_DIR` overrides the directory; the file name stays `ops.log`. An empty `AXLE_LOG_DIR`, or a missing `LOCALAPPDATA`, writes nothing. The directory is created on the first logged event, not at install time. Tests write no log unless `AXLE_LOG_DIR` is set. A symlink log directory or a symlink `ops.log` is refused via `symlink_metadata` (the link is not followed).
- `sanitize_terminal_text` strips CSI, OSC, carriage return, C1 controls U+0080–U+009F, and DCS, SOS, PM, and APC through ESC \ or BEL. `truncate_title` cuts on a UTF-8 char boundary before the ellipsis.
- `InstallEvent::AllFinished` without per-item results is not a clean success. Queued rows become Failed (`No item result arrived`) and the status is `Install did not finish cleanly.`
- Versioning follows Cargo.toml. Before 1.0.0, commits since the last `v*` tag decide the bump: a user-facing break or `BREAKING CHANGE` raises MINOR (do not jump to 1.0.0 unless the user asks); a `feat` raises MINOR; otherwise a `fix` raises PATCH. The highest change wins. From 1.0.0 on, a break raises MAJOR, a `feat` raises MINOR, and a `fix` raises PATCH. Cargo.toml, the axle-tui entry in Cargo.lock, and tag `v{version}` stay identical. Tag and push only when the user asks for a release. A `v*.*.*` tag triggers `.github/workflows/release.yml` (Windows zip). crates.io publish stays a separate explicit request.
